# A2UI: уточнение в существующем текстовом стриме

Минимальный **UI-only** пример: React + Ant Design + официальный `@a2ui/react` (0.12.0, протокол v0.9). Агент задаёт вопрос с вариантами; карточка отправляет выбранный ответ через callback вашего приложения. Бэкенда, клиента DeepSeek и собственного сетевого запроса здесь нет.

## Перенести в ваш готовый UI и чат

Копируйте **только [`src/a2ui`](src/a2ui)**. Внутри — компоненты, каталог, контракт, контроллер, декодер и хук `useA2ui`. Модуль не импортирует демо или чат и не делает запросов. [Карта файлов и API](src/a2ui/README.md); [подключение по шагам](docs/integration.md).

| Каталог | Что переносить |
| --- | --- |
| `src/a2ui` | Весь переносимый модуль |
| `src/example` | Необязательный пример адаптера к вашему запросу |
| `src/demo` | Эмулятор чата/стрима; не нужен в приложении |

`useA2ui({ onAnswer })` отдаёт `controller`, `beginResponse({ onText, onError })` и `clear()`. Декодер ответа имеет `push`, `finish`, `cancel`. Обычный текст передаётся в ваш store через `onText`, выбранный вариант — вашему запросу через `onAnswer`.

Для переноса только исходников модуля:

```bash
npm run package:a2ui
```

В `releases/a2ui-source.tar.gz` находится только каталог `a2ui` с инструкцией; рядом SHA256. Зависимости не входят в архив: подготовьте их во внутреннем registry/кэше. Корневые конфиги, демо, tests и scripts копировать в ваш проект не нужно.

## Проверить демо

Node.js 24 и npm:

```bash
npm ci
npm run dev
```

Откройте URL Vite, нажмите «Запустить», дождитесь карточки и выберите вариант. Демо эмулирует стрим по одному символу. Можно включить ошибку отправки, нажать вариант, выключить ошибку и повторить отправку. `npm run check` проверяет типы, тесты и сборку.

## Начать с фронта и запроса

Компилируемый адаптер: `src/example/AgentChat.tsx`. Полный пример подключения с импортами: **[docs/integration.md](docs/integration.md)**. Исходники можно скопировать из `src/a2ui` в ваше приложение или установить собранный локальный пакет:

```bash
npm run build:lib
npm pack
# В вашем приложении:
npm install /path/to/kxnzee-a2ui-clarification-ui-0.1.0.tgz
```

Пакет не опубликован в npm. React и ReactDOM предоставляет приложение. Если у вас другая версия AntD, при копировании исходников согласуйте её API (пример использует AntD 6).

## Как проходит ответ

1. Ваш существующий запрос запускает стрим агента.
2. Декодированные текстовые чанки передаются в `stream.push(delta)`.
3. Обычный текст попадает в `onText`. Полный блок `<clarification>…</clarification>` проверяется Zod и передаётся контроллеру.
4. Контроллер строит сообщения A2UI и рендерит зарегистрированный `ClarificationCard` из AntD.
5. Нажатие возвращает `{ type, questionId, optionId, label }` в `onAnswer`. Здесь вызывается ваш существующий запрос. Ответ агента опять проходит через новый декодер.

Теги — **контракт этого примера поверх текстового стрима**, а не стандарт A2UI. На проводе от агента идёт небольшой JSON вопроса; UI преобразует его в реальные сообщения A2UI. Каталог хранится в `src/a2ui/catalog.tsx`; модель получает контракт JSON и инструкции из `src/a2ui/contract.ts`, а не React-компонент. Если ваш агент уже выдаёт сырые сообщения A2UI, нужен другой декодер.

## Закрытый контур

Самый простой путь: собрать статику в среде с зависимостями и перенести результат:

```bash
npm ci
npm run build
npm run package:demo
```

Перенесите `releases/a2ui-clarification-demo.tar.gz` и файл `.sha256` в контур, проверьте `sha256sum -c a2ui-clarification-demo.tar.gz.sha256`, распакуйте архив в каталог вашего HTTP-сервера. `package:demo` требует утилиту `tar`. Вместо архива можно просто перенести `dist/demo`. Подкаталоги поддерживаются благодаря относительным путям. Открывайте через HTTP, не через `file://`.

Готовому демо не нужны npm, Node.js, CDN, внешние шрифты или интернет; запросы агента эмулируются. Для настоящего приложения соберите UI вместе с вашим приложением и существующим транспортом во внутренний агент. Библиотека не устанавливает сетевых соединений. В CI доступен артефакт `clarification-demo`.

Если сборка должна выполняться внутри контура, зависимости нужно заранее доставить через ваш внутренний npm registry или подготовленный npm cache. Один `package-lock.json` не содержит пакеты; кэш должен включать платформенные зависимости Vite для ОС/архитектуры сборки.

## Что проверяется и что остаётся приложению

Декодер принимает **строковые дельты**, не накопленный текст, SSE-конверты или байты; SSE и UTF-8 декодирует ваш транспорт. Карточка появляется только после закрывающего тега и успешной валидации. Неверный/оборванный JSON не рендерится, ошибка возвращается в `onError`. Гарантии, что модель всегда выдаст валидный JSON, нет; здесь гарантируется отказ UI от невалидной карточки. Повтор генерации и constrained decoding при необходимости настраиваются в вашей интеграции агента.

Карточка блокирует повторные клики при отправке и после успеха; при ошибке позволяет повторить. Возвращаемый Promise должен отражать реальное принятие ответа вашим транспортом. Серверная идемпотентность и повторные доставки остаются ответственностью приложения.

Тесты проверяют границы чанков, JSON, схему, размер блока, действия настоящего A2UI, повторные клики, ошибки и смену вопроса. Реальный DeepSeek и ваш транспорт не вызываются.
