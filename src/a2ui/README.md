# Переносимый модуль A2UI: два компонента

**Копируйте весь этот каталог** в своё React-приложение, например `src/features/a2ui`. Демо, пример чата, Vite-конфиги и scripts переносить не нужно. Публичный вход — `index.ts`.

| Файл | Ответственность |
| --- | --- |
| `useA2ui.ts` | React lifecycle, подключение чанков, отмена декодера, очистка |
| `A2uiView.tsx` | Рендер текущей поверхности A2UI |
| `catalog.tsx` | Регистрация `ClarificationCard` и `MetricCard`, AntD-разметка |
| `controller.ts` | Выбор компонента по type, сообщения A2UI, событие выбора |
| `stream.ts` | Извлечение проверенного JSON из текстовых дельт |
| `contract.ts` | Схемы двух типов, тип ответа, инструкции выбора для агента |
| `index.ts` | Публичные экспорты |

Нет fetch, URL агента, импорта чата, истории сообщений, роутинга или конфигурации приложения. Используется существующий React/ReactDOM и ваш AntD ConfigProvider.

Зависимости: `@a2ui/react@0.12.0`, `@a2ui/web_core@0.12.0`, `zod@3.25.76`, `antd@6.6.5`; React/ReactDOM 18.2 или 19. Для AntD 5 адаптируйте только `catalog.tsx`: `Space.orientation` → `direction`, `Alert.title` → `message`. AntD 5 здесь не проверялся. Зависимости подготовьте во внутреннем registry/кэше; исходный архив их не включает.

## Подключение к вашему чату

```tsx
import { useA2ui, A2uiView } from './features/a2ui';

// В компоненте существующего чата:
const a2ui = useA2ui({
  onAnswer: answer => existingSendAnswer(answer), // Promise принятия ответа
});

// Один раз перед каждым ответом агента, не во время рендера:
const response = a2ui.beginResponse({
  onText: delta => appendToExistingMessage(delta),
  onError: error => showExistingChatError(error.message),
});

// В callbacks существующего транспорта:
// onTextDelta → response.push(delta)
// onDone      → response.finish()
// onCancel / onError → response.cancel()

// В существующей разметке:
<A2uiView controller={a2ui.controller} />
```

Новый `beginResponse` отменяет старый декодер. Транспорт отменяет приложение; модуль не управляет запросом. `push` принимает текстовые дельты, а не SSE-конверты, байты или накопленный текст. Чат показывает текст из `onText`, чтобы служебный JSON не появлялся пользователю.

`a2ui.clear()` отменяет декодер и убирает карточку. Для разных диалогов создайте отдельные экземпляры хука, например через `key={conversationId}`. При unmount декодер отменяется и контроллер закрывается; поздние чанки завершённых/отменённых ответов игнорируются. Актуальный `onAnswer` используется после rerender.

## Как агент выбирает компонент

Передайте `A2UI_INSTRUCTIONS` в системные инструкции вашей существующей интеграции. В строке уже есть назначение типов, правила выбора, ограничения и примеры. Локальной модели интернет не нужен; регистрация React-компонента сама по себе не сообщает о нём модели.

| type | Когда выбирать | React-компонент | Событие |
| --- | --- | --- | --- |
| `clarification` | Нужен выбор пользователя для продолжения | `ClarificationCard` | `onAnswer` |
| `metric` | Нужно показать одно известное числовое значение | `MetricCard` | Нет |

Агент передаёт `{type, props}` внутри `<ui>…</ui>`; фронт проверяет схему и явно выбирает зарегистрированную реализацию. Обычный текст остаётся вне блоков. Неизвестный тип или неверные props отклоняются через `onError`; произвольный JSX не исполняется.

Уточнение:

```text
Уточню один момент.
<ui>{"type":"clarification","props":{"questionId":"metric-1","question":"Что показать?","options":[{"id":"revenue","label":"Выручка"},{"id":"orders","label":"Заказы"}]}}</ui>
```

После клика `onAnswer` получает `{type: 'clarification_answer', questionId, optionId, label}`. Ваш существующий запрос отправляет ответ в тот же диалог. Promise должен отклоняться при ошибке отправки: UI позволяет повторить выбор.

Затем агент может показать числовой результат:

```text
Вот показатель за выбранный период.
<ui>{"type":"metric","props":{"title":"Выручка","value":1250000,"unit":"₽"}}</ui>
```

`metric.value` — конечное число, не строка; отрицательные значения, дробные и ноль поддерживаются. `unit` необязательна. Числа берёт агент из ваших данных; UI проверяет структуру, но не достоверность показателя. В демо числа тестовые.

Карточка появляется только после полного блока и успешной проверки. Показывается **одна текущая карточка**: следующий блок заменяет предыдущий. Историю карточек хранит ваше приложение, если она нужна. Новый вопрос должен иметь новый questionId. Теги `<ui>` — контракт примера поверх текста, а не стандарт протокола A2UI.

## Обновление предыдущего примера

Общий контракт заменил `<clarification>…</clarification>` на `<ui>{"type":"clarification","props":…}</ui>`. Старый тег больше не обрабатывается как компонент. Используйте `A2UI_INSTRUCTIONS`, `A2uiView`, `createA2uiController`, `createA2uiStream`; прежние имена, привязанные только к clarification, удалены. API `useA2ui` и подключение чанков остались прежними.
